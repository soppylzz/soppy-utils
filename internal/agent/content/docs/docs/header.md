# Documentation

Write for the person who arrives without context, because that is everyone eventually,
including you.

- Lead with what it does, then how to use it, then how it works. Most readers stop after
  the first.
- Show a working example before describing the options. An example that runs answers more
  questions than a paragraph that explains.
- Keep one document per topic. A document that answers three questions is found by none
  of them.
- Say what is *not* supported. A limit stated is a support question that is never asked.
- Update the document in the change that makes it wrong. A follow-up task to fix the docs
  is a task that does not happen.
