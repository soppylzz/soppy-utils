# Keeping documentation true

A document drifts the moment the code moves and nobody reads both.

- Treat a stale document as a defect, not as debt. It is actively misleading, which is
  worse than absent.
- When behaviour changes, the change is not finished until the document that describes it
  has changed too.
- Version a document that describes versioned behaviour. Put the version in the filename
  or in the frontmatter, and keep the old one rather than rewriting history.
- Delete a document that no longer describes anything. A repository accumulates documents
  that are partly true, and a reader cannot tell which parts.
- Prefer one maintained document to three abandoned ones.
